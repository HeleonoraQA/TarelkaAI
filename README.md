# Tarelka

**Планировщик домашнего питания.** Недельный план, рецепты и список покупок — в одном приложении. Данные хранятся только на устройстве: без аккаунтов, бэкенда и аналитики.

«Раз в неделю собрать план, один раз сходить в магазин и готовить без лишних решений.»

## Что это

Tarelka — веб-приложение (PWA) для планирования домашнего питания. Пользователь проходит короткий онбординг (категория питания, аллергии, количество человек), получает **готовый план на неделю** и **автоматически собранный список покупок** по отделам магазина.

**Для кого:** занятые люди 25–45 лет, готовят дома 3–5 раз в неделю, хотят есть разнообразно и не тратить час на планирование.

**Главный сценарий:**
Онбординг (3 шага) → План недели → Рецепт → Список покупок

**Принципы:**

1. План важнее каталога — главный экран это неделя, а не лента рецептов.
2. Готовый результат с первого запуска — онбординг заканчивается планом, а не пустым экраном.
3. Только тапы — никаких свайпов, долгих нажатий и drag-and-drop.
4. План и список — одно целое: изменение плана сразу отражается в покупках.
5. Приватность по умолчанию — данные не покидают устройство.

## Возможности MVP

### Онбординг
- 3 шага: категория питания → аллергии → количество человек (2/4/6).
- Категории: «Без ограничений», «Много белка», «Лёгкое», «Щадящее». «Без ограничений» показывает весь каталог.
- Любой шаг можно пропустить, значения по умолчанию: «без ограничений», без аллергий, 4 человека.
- Настройки меняются позже в «Ещё → Мои предпочтения».

### План недели
- 7 дней (пн–вс) × 3 приёма пищи (завтрак / обед / ужин).
- Сегодняшний день выделен и `aria-current="date"`.
- Назначение рецепта в пустую ячейку через Discover.
- Удаление блюда с возвратом фокуса.
- «Собрать заново» — автоподбор по категории питания и аллергиям с минимумом повторов.

### Discover (выбор рецепта)
- Открывается из пустой ячейки плана; день уже выбран.
- Поиск по названию и ингредиентам.
- Фильтры-чипы: «До 20 минут», «Завтрак», «Обед», «Ужин».
- Жёсткие ограничения (категория питания + аллергии) применяются всегда.

### Карточка рецепта
- Крупное фото, название, вступление, время, порции, теги.
- Пересчёт порций 2 / 4 / 6: штучные округляются вверх, граммы и мл — до 5.
- «Добавить в список» — добавляет ингредиенты в покупки.
- «Добавить в план» / «Добавить сюда» (если пришли из ячейки).
- Дисклеймер по аллергенам.

### Список покупок
- Собирается автоматически из плана: агрегация по `name + unit + dept`.
- Группировка по 7 отделам в фиксированном порядке.
- Отметка купленного одним тапом + прогресс «X из Y».
- Ручное добавление позиций.
- Отметки сохраняются при изменении плана.

### Ещё
- «Мои предпочтения»: категория питания, аллергии, порции 2/4/6; сохранение сразу влияет на следующий автоподбор.
- «Данные»: «Сбросить всё» с подтверждением, после сброса — онбординг.
- «О продукте»: дисклеймер по аллергенам, локальное хранение, версия.

## Технологии и ограничения

| Слой | Что используем | Что **не** используем |
|---|---|---|
| HTML | Семантический HTML5 | — |
| CSS | Чистый CSS + CSS-переменные (`styles/tokens.css`) | Tailwind, Bootstrap, препроцессоры |
| JS | Vanilla JS (ES5-совместимый IIFE) | React, Vue, Svelte, jQuery, lodash |
| Сборка | Нет | npm, bundlers, транспайлеры |
| Шрифты | Системный стек + Inter, если установлен | Google Fonts, CDN |
| Иконки | Инлайн SVG-спрайт (Lucide-style) | Библиотеки иконок, внешние запросы |
| Хранение | `localStorage` (один ключ `tarelka:state`) | IndexedDB, бэкенд |
| Изображения | Локальные SVG-плейсхолдеры (в финале — WebP) | Внешние URL |

**Жёсткие правила** (см. `AGENTS.md`):
- Все цвета, отступы, радиусы — только через токены в `styles/tokens.css`.
- Хардкод цветов в `main.css` и `app.js` запрещён.
- Внешних сетевых запросов нет: приложение работает офлайн после первого открытия.
- Данные пользователя не покидают устройство.

Подходит любой статический хостинг: GitHub Pages, Netlify, Vercel, Cloudflare Pages.

Settings → Pages → Source: Deploy from a branch → main / / (root).

Откройте https://<user>.github.io/<repo>/.

После первого визита приложение кэшируется и работает офлайн.

## Безопасность данных:

Чтение в try/catch, валидация структуры.

Повреждённое значение копируется в tarelka:state:corrupt (без перезаписи оригинала).

Неизвестная версия схемы → мягкий старт с чистого состояния + тост.

При ошибке записи (приватный режим, квота) — тост, UI не ломается.

Подробнее — docs/spec.md.

**Список покупок**
Список не хранится — он выводится из плана + ручных позиций + отметок:

для каждого рецепта в плане:
    factor = profile.people / recipe.servings
    amount = ingredient.amount × factor
Правила округления:

Единица	Правило
шт, зуб., банка, ломтика	Вверх до целого, минимум 1
г, мл	До 5, минимум 5
ст. л., ч. л.	До 0,5
Пусто / «по вкусу»	Не умножается, выводится «по вкусу»
Дедупликация: ингредиенты с одинаковыми name + unit + dept суммируются. Разные единицы одного продукта остаются разными строками.

Отметки привязаны к ключу plan|dept|name|unit, поэтому переживают изменение порций и пересборку плана.

**Фильтры подбора**
Рецепт попадает в Discover и «Собрать заново», если:

Категория питания: none — любой рецепт; protein — categories содержит protein; light — содержит light; gentle — содержит gentle.
Рецепт может входить в несколько категорий; «Без ограничений» не фильтрует каталог.

Аллергены: ни один выбранный аллерген не входит в recipe.allergens.

Дополнительно в Discover:

поиск по названию и ингредиентам;

«До 20 минут» (recipe.time ≤ 20);

фильтр по приёму пищи (тег «Завтрак» / «Обед» / «Ужин»).

## Дизайн и UX
Визуальная концепция — тёплый пастельный wellness-food. Источник — design.md.

Палитра (все значения — в styles/tokens.css):

Токен	HEX	Назначение
--color-bg	#FBF6EE	Тёплый кремовый фон
--color-surface	#FFFDF9	Карточки
--color-primary	#B8432E	Томатно-паприковый акцент
--color-secondary	#557351	Шалфей (успех, чекбоксы)
--color-text	#2E2622	Тёплый тёмно-коричневый
--color-text-muted	#6E625B	Вторичный текст
Типографика:

Заголовки: Inter (если установлен) → системный стек.

Текст: системный стек (-apple-system, Segoe UI, Roboto).

Внешние шрифты не загружаются — это сохраняет офлайн и отсутствие внешних запросов.

Компоненты:

Карточка рецепта: фото 16:9 сверху, радиус 16px, мягкая тень.

Chip-фильтр: пилюля, aria-pressed для активных.

Чекбокс: 28×28, зона клика 44×44, зачёркивание при отметке.

Toast: снизу, role="status", не забирает фокус.

Discover: bottom sheet на мобиле, модалка ≥ 768px.

Чего избегаем:

Чистый белый #FFFFFF как основной фон.

Холодные цвета (синий, циан) и неон.

Острые углы < 8px.

Тяжёлые чёрные тени и градиенты.

Анимации > 300ms.

PWA и офлайн
manifest.json:

display: standalone

theme_color: #B8432E (совпадает с --color-primary)

background_color: #FBF6EE (совпадает с --color-bg)

иконки 192, 512, maskable 512

sw.js:

CACHE_VERSION = 'tarelka-v3' — версия кэша в имени.

При изменении списка файлов — поднять версию.

Навигация: network-first с фолбэком на кэш.

Статика: network-first с обновлением кэша.

Не-GET и чужие origin — не трогаем.

Что работает офлайн: онбординг, план, рецепт, покупки, настройки — после первого успешного открытия.

Установка на домашний экран:

Chrome/Edge (Android, desktop): кнопка «Установить» в адресной строке.

Safari (iOS): «Поделиться» → «На экран "Домой"».

## Что НЕ входит в MVP
Осознанные границы (см. docs/discussion.md и docs/prd.md, раздел 3.2):

Отдельная вкладка каталога и лента вдохновения.

Избранное, рейтинги, комментарии, сообщество.

Полноэкранный кулинарный режим с таймерами.

Импорт рецептов по URL и свои рецепты.

Аккаунты, синхронизация, шаринг.

Несколько недель и история планов.

Калории, БЖУ, health score, дневник питания.

AI-подбор и рекомендации на основе поведения.

Доставка, магазины, цены, штрихкоды.

Подписки, реклама, партнёрские ссылки.

Печать, копирование в буфер, экспорт/импорт JSON.

Свайпы, долгие нажатия, drag-and-drop.

Тёмная тема, кастомизация, мультиязычность.

Push-уведомления, аналитика, трекинг.

Любой пункт возвращается только через отдельное обсуждение и обновление документов.

## Проверка перед PR
**Функциональность**
□ Первый запуск показывает онбординг; после «Собрать план» — «План».
□ Перезагрузка сохраняет диету, аллергии и число человек.
□ Назначение рецепта заполняет ячейку и появляется в покупках.
□ Одинаковые ингредиенты суммируются, купленное остаётся отмеченным.
□ Чекбоксы и ручные позиции переживают перезагрузку.
□ Повреждённый JSON не ломает приложение.
□ Офлайн-перезагрузка после первого визита работает.
**Доступность**
□ Все действия доступны с клавиатуры.
□ Фокус видим и логичен.
□ В Discover фокус-трап и Esc закрывает.
□ Контраст текста ≥ 4.5:1.
□ Нет горизонтального скролла на 360px.
□ Работает со скринридером (VoiceOver / NVDA / TalkBack).
**Производительность**
□ Первая загрузка ≤ 1.5 МБ.
□ LCP ≤ 2.5s на медленном 4G.
□ CLS < 0.1 (у изображений заданы размеры).
□ Нет внешних запросов (Network panel: только same-origin).
**PWA**
□ Устанавливается на домашний экран.
□ Работает в standalone-режиме.
□ После первого визита работает офлайн.
Документация
□ Изменения отражены в docs/ и design.md до кода.
□ Цвета и отступы — только через токены.
□ Нет хардкода в main.css и app.js.
Известные расхождения
Текущий прототип опережает PRD в нескольких местах. Все расхождения зафиксированы в docs/spec.md, раздел 10:

## Лицензия
Проект учебный. Все названия продуктов (Mealime, Kitchen Stories, Yummly, Whisk, AnyList) принадлежат их владельцам и использованы в исследовательских целях (docs/research.md). Изображения блюд — локальные SVG-плейсхолдеры; источники финальных фото должны быть указаны в реестре источников.
