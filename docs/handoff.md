## 2. Краткое резюме

> Ниже — продуктовые решения. Что уже есть в прототипе, а что зафиксировано только в PRD, помечено в §3.

1. Tarelka — планировщик питания: недельный план, рецепты и список покупок; без бэкенда, аккаунтов и аналитики.
2. Стек MVP — только HTML, CSS и JavaScript, mobile-first PWA; все данные в одном версионированном ключе `tarelka:state`.
3. Главный сценарий: онбординг → автоплан на текущую неделю → добавление или замена блюд → рецепт → список покупок.
4. Онбординг по PRD — 4 шага: тип питания, аллергии, нелюбимые продукты, порции 2/4/6; каждый шаг можно пропустить. В прототипе шагов три, шага «нелюбимые продукты» нет.
5. Ограничения: тип питания и аллергии — жёсткие фильтры; нелюбимые продукты исключаются только из автоподбора (в прототипе не реализовано).
6. Контент: 18 своих рецептов в локальном JSON и локальные SVG-иллюстрации.
7. Данные: одна активная неделя и один шаблон; ручные позиции и отметки покупок сохраняются при изменениях плана. Шаблон в прототипе не реализован.
8. UX: три вкладки «План», «Покупки», «Ещё»; только тапы; оптимистичные обновления с откатом и undo на 5 секунд (undo в прототипе не реализован).
9. Доступность и производительность: WCAG 2.1 AA, зоны 44×44, клавиатура, 360 px; автоподбор ≤ 2 с, первая загрузка ≤ 1,5 МБ.
10. Границы: нет каталога, избранного, кулинарного режима, аккаунтов, синхронизации, печати, экспорта, тёмной темы и AI.

| Решение | Детали | В прототипе |
| :-- | :-- | :-- |
| **Главный экран** | Неделя пн–вс, сегодняшний день выделен. | Есть |

| **Повторы** | Разрешены. Порции складываются, одинаковые ингредиенты в одной единице суммируются. | Есть |

| **Диалоги** | Полноэкранный диалог на всех ширинах; bottom sheet в MVP не используется (PRD A5). | Есть: контент колонкой до 760 px |
| **Обратимость** | Удаление, перемещение, замена и смена порций — с undo на 5 секунд. Сброс и шаблон — с подтверждением. | Подтверждение сброса есть; undo нет |

| **Приватность** | Нет внешних запросов, шрифтов с CDN, аналитики и трекинга. | Есть |
