# SPEC: состояние, план и покупки

**Версия:** 1.3  
**Версия продукта:** 1.0  
**Дата:** 5 ноября 2026  
**Статус:** рабочая спецификация текущего прототипа  
**Связанные документы:** `docs/prd.md`, `docs/ux-flows.md`, `docs/design.md`, `AGENTS.md`

> Документ описывает то, что уже реализовано в `js/app.js` и `js/data.js`. PRD остаётся контрактом объёма: расхождения перечислены в разделе 10 и требуют синхронизации документов.

## 1. Хранилище

Один ключ `localStorage`:

```
tarelka:state
```

Одно значение — JSON-объект текущей версии. Отдельных ключей для профиля, плана и покупок нет.

### 1.1. Схема (version 1)

`version` — версия схемы хранилища, а не версия продукта. Версия продукта отображается в «Ещё» и «О продукте» и равна 1.0.

```json
{
  "version": 1,
  "profile": {
    "onboarded": true,
    "diet": "none",
    "allergies": ["gluten"],
    "people": 4
  },
  "plan": [
    {
      "breakfast": "oatmeal",
      "lunch": "soup",
      "dinner": "pasta"
    }
  ],
  "checked": {
    "plan|veg|Томаты|шт": true
  },
  "manual": [
    {
      "id": "m1730553600000",
      "name": "Бумажные полотенца",
      "amount": "",
      "dept": "other",
      "source": "вручную"
    }
  ],
  "updatedAt": "2026-11-02T10:00:00.000Z"
}
```

| Поле | Тип | Правила |
| :-- | :-- | :-- |
| `version` | number | Всегда `1`. Неизвестная версия → миграция или сброс. |
| `profile.diet` | string | `none`, `protein`, `light`, `gentle`. Старые значения `vegetarian`, `vegan`, `pescatarian` при загрузке превращаются в `none`. |
| `profile.allergies` | string[] | Подмножество `gluten`, `nuts`, `milk`, `eggs`, `fish`, `soy`. |
| `profile.people` | number | Только `2`, `4`, `6`. |
| `plan` | array | Ровно 7 элементов. Ключи `breakfast`, `lunch`, `dinner`; значение — `id` рецепта или `null`. |
| `checked` | object | Ключ позиции → `true`. Отсутствие ключа = не куплено. |
| `manual` | array | Позиции, добавленные вручную. `id` уникален. |
| `updatedAt` | string | ISO-дата последнего сохранения. |

`plan` не привязан к календарным датам: это одна активная неделя. Даты и «сегодня» вычисляются при отрисовке от текущего понедельника и в хранилище не попадают.

### 1.2. Загрузка и повреждённые данные

1. Значение читается и парсится в `try/catch`.
2. Структура валидируется: версия, типы, допустимые значения, длина плана, существование `id` рецептов.
3. Невалидное или повреждённое значение:
   - сырая строка копируется в `tarelka:state:corrupt` (с перезаписью — храним последнюю аварию, а не бесконечную историю);
   - приложение стартует с дефолтным состоянием;
   - пользователь видит тост «Не удалось прочитать сохранённые данные. Начали с чистого листа».
4. Ошибка записи (приватный режим, квота) не ломает UI: показывается тост «Не удалось сохранить изменения».

Сохранение — после каждого дискретного действия: завершение онбординга, назначение/удаление блюда, чекбокс, добавление/удаление ручной позиции, смена порций.

## 2. Профиль и онбординг

- Три шага: категория питания → аллергии → количество человек. Значения по умолчанию: `none`, без аллергий, `4`.
- Категории питания: «Без ограничений» (`none`), «Много белка» (`protein`), «Лёгкое» (`light`), «Щадящее» (`gentle`). Рецепт может входить сразу в несколько категорий; «Без ограничений» не фильтрует каталог и показывает все блюда.
- Те же три поля меняются после онбординга в «Ещё → Мои предпочтения».
- «Пропустить» и «Собрать план» сохраняют то, что выбрано, ставят `onboarded: true` и открывают «План».
- При повторном запуске с `onboarded: true` онбординг не показывается, форма предзаполняется сохранёнными значениями.
- Смена количества человек в карточке рецепта меняет `profile.people` глобально и пересчитывает ингредиенты и покупки.

## 3. Фильтры подбора

Рецепт попадает в подборку (Discover и «Собрать заново»), если выполнены оба условия:

1. **Категория питания:** `none` — любой рецепт; `protein` — `recipe.categories` содержит `protein`; `light` — содержит `light`; `gentle` — содержит `gentle`.
2. **Аллергены:** ни один выбранный аллерген не входит в `recipe.allergens`.

### 3.1. Каталог и категории

В прототипе 18 рецептов. Один рецепт может относиться к нескольким категориям, поэтому счётчики пересекаются.

| Категория | Рецептов | Примеры |
| :-- | :-- | :-- |
| Много белка (`protein`) | 11 | куриный суп, омлет, лосось, сырники, курица, тосты, треска, тефтели, индейка, тунец |
| Лёгкое (`light`) | 12 | паста, овсянка, омлет, гречка, салат, лосось, треска, рисовая каша, тыквенный суп, запечённое яблоко, рагу, тунец |
| Щадящее (`gentle`) | 10 | куриный суп, овсянка, тушёная курица, треска, рисовая каша, тефтели, тыквенный крем-суп, запечённое яблоко, индейка, кабачковое рагу |

«Щадящее» — противовоспалительные и мягкие для ЖКТ блюда: варка, тушение, запекание, пар, без острого и жареного. «Лёгкое» — овощные, злаковые и другие легкоусвояемые блюда. «Много белка» — блюда с преимущественным содержанием белка.

Уже назначенные блюда из плана не исключаются: фильтр действует на автоподбор, а не прячет содержимое. Нелюбимые продукты (dislikes) в текущем прототипе не реализованы — поля и шага онбординга нет.

Дополнительно в Discover работают поиск (название + ингредиенты), «До 20 минут» и фильтр по приёму пищи (тег «Завтрак» / «Обед» / «Ужин»).

## 4. Назначение рецепта

- Пустая ячейка → Discover с заголовком «Добавить в Вт, обед».
- «＋» в строке рецепта назначает его в целевую ячейку, сохраняет состояние, закрывает оверлей и показывает тост.
- Тап по строке открывает карточку рецепта; там доступна кнопка «В Вт, обед».
- У назначенного блюда есть кнопка «Убрать из плана» (иконка `×`) с `aria-label`; удаление сохраняется сразу.
- Замена блюда: удалить и назначить заново либо открыть Discover из карточки.

## 5. Покупки

Список не хранится как готовый массив: он **выводится** из плана, ручных позиций и отметок.

### 5.1. Агрегация

Для каждого рецепта в плане:

```
factor = profile.people / recipe.servings
amount = recipe.amount × factor
```

Правила округления:

| Единица | Правило |
| :-- | :-- |
| `шт`, `зуб.`, `банка`, `ломтика` | Вверх до целого, минимум 1. |
| `г`, `мл` | До 5, минимум 5. |
| `ст. л.`, `ч. л.` | До 0,5. |
| Пусто / «по вкусу» | Количество не считается, выводится «по вкусу». |

Дедупликация: ингредиенты с одинаковыми `name` + `unit` + отделом суммируются в одну позицию. Разные единицы одного продукта остаются разными строками.

Отдел определяется по `data.ingredientCategories`; нет совпадения → «Прочее».

### 5.2. Ключи и чекбоксы

- Позиция плана: `plan|<dept>|<name>|<unit>`.
- Ручная позиция: `manual|<id>`.
- Отметка хранится в `checked[key]`; ключ не зависит от количества, поэтому отметка переживает изменение порций и пересборку плана.
- Удаление продукта из плана убирает позицию из списка, но отметка остаётся в `checked` (безвредный мусор, чистится при сбросе).

### 5.3. Ручные позиции

- Форма «Что купить?» добавляет позицию в отдел «Прочее» с `source: "вручную"`.
- Ручную позицию можно удалить (иконка `×`), тогда же удаляется её отметка.
- «Добавить в список» в карточке рецепта добавляет ингредиенты как ручные позиции с `source: "из рецепта"`; дубликаты по названию и отделу пропускаются.

## 6. Пересборка недели

«Собрать заново»:

1. Спрашивает подтверждение (текущие блюда будут заменены).
2. Для каждой из 21 ячейки выбирает случайный подходящий рецепт с тегом приёма пищи.
3. Сохраняет и перерисовывает план и покупки.

## 7. Навигация

- `body[data-screen]` управляет видимым экраном; секции — `.screen[data-screen]`.
- Стек навигации: «Назад» из рецепта возвращает на предыдущий экран (план или Discover), из Discover — на план.
- «Ещё» открывается из нижней навигации; «Мои предпочтения», «Данные» и «О продукте» — вложенные экраны, «Назад» возвращает в «Ещё».
- Discover — полноэкранный диалог на всех ширинах: `role="dialog"`, `aria-modal="true"`, фокус переносится в заголовок, Tab замыкается внутри экрана, Escape закрывает.
- Фокус после удаления блюда возвращается на освободившуюся ячейку.

### 7.1. «Ещё», предпочтения, данные и «О продукте»

**«Ещё»** — хаб из трёх строк-переходов и версии приложения:

| Строка | Содержимое |
| :-- | :-- |
| Мои предпочтения | Сводка: категория, аллергии, количество человек |
| Данные | «Хранятся только на этом устройстве» |
| О продукте | Версия приложения (1.0) |

**«Мои предпочтения»** — форма с теми же контролами, что в онбординге: 4 категории, 6 аллергенов, порции 2/4/6.

- «Сохранить» обновляет `profile` в `tarelka:state`, применяет ограничения к следующему автоподбору и Discover и пересчитывает покупки под новое число порций.
- Текущий план не очищается. Если в нём есть блюда, не подходящие под новые ограничения, показывается предупреждение с кнопкой «Собрать заново»; пересборка идёт через обычное подтверждение.
- Нелюбимые продукты и сохранённая неделя в прототипе не реализованы.

**«Данные»** — объяснение, что план, покупки и настройки лежат только в `localStorage`, и кнопка «Сбросить всё».

- Сброс требует подтверждения; фокус по умолчанию — на «Отмена».
- После подтверждения удаляются `tarelka:state` и `tarelka:state:corrupt`, показывается тост «Данные сброшены», страница перезагружается в онбординг.
- Если запись в `localStorage` недоступна, показывается тост с ошибкой, интерфейс продолжает работать.

**«О продукте»** — короткое описание, дисклеймер по аллергенам, «данные не покидают устройство», источник иллюстраций (собственные SVG) и версия приложения (1.0).

## 8. PWA и офлайн

- `manifest.json`: `standalone`, `theme_color` `#B8432E`, `background_color` `#FBF6EE`, иконки 192/512 и maskable 512.
- `sw.js`: precache оболочки (HTML, CSS, JS, manifest, иконки, SVG рецептов), версия кэша в имени.
- Стратегии: навигация и статика — network-first с обновлением кэша; при ошибке сети или ответе не-`ok` (502, 503 и т. п.) отдаётся сохранённая копия, если её нет — ответ сети как есть; не-GET и внешние origin не кэшируются.
- Внешних запросов нет: шрифты системные, изображения локальные.

## 9. Доступность

- Управление только тапами и клавиатурой; свайпов, долгих нажатий и drag-and-drop нет.
- Интерактивные зоны не меньше 44 × 44 px.
- Иконки-кнопки имеют `aria-label`; статусы объявляются через `role="status"`.
- Контраст текста и элементов — не ниже WCAG AA.
- `prefers-reduced-motion` отключает анимации.

## 11. Чек-лист проверки

- [ ] Первый запуск показывает онбординг; после «Собрать план» — «План».
- [ ] Перезагрузка сохраняет категорию питания, аллергии и число человек.
- [ ] В каждой категории «Много белка», «Лёгкое», «Щадящее» не меньше 10 блюд.
- [ ] Старое значение диеты (`vegetarian` и т.п.) не ломает загрузку и превращается в «Без ограничений».
- [ ] Назначение рецепта заполняет ячейку и появляется в покупках.
- [ ] Одинаковые ингредиенты суммируются, купленное остаётся отмеченным.
- [ ] Чекбоксы и ручные позиции переживают перезагрузку.
- [ ] «Ещё → Мои предпочтения» сохраняет категорию, аллергии и порции; они применяются к следующему автоподбору.
- [ ] «Ещё → Данные → Сбросить всё» очищает состояние после подтверждения и возвращает онбординг.
- [ ] «Ещё → О продукте» показывает дисклеймер и версию.
- [ ] Повреждённый JSON не ломает приложение.
- [ ] Офлайн-перезагрузка после первого визита работает.
- [ ] Нет горизонтального скролла на 360 px; клавиатура проходит все действия.
