## Что делаем

### Главный сценарий

1. Пользователь впервые открывает Tarelka и проходит онбординг из 4 шагов. Любой шаг можно пропустить.
2. Сразу после онбординга получает план на неделю, собранный по правилам и тегам. Это не пустой экран, а готовый результат, который можно менять.
3. Открывает день, добавляет или заменяет блюдо из подборки рецептов.
4. Открывает рецепт, смотрит ингредиенты и шаги, при необходимости меняет число порций.
5. Переходит в покупки: список уже собран из плана, остаётся отметить купленное.
6. Меняет план — список обновляется, ручные позиции и отметки не теряются.

### Экраны MVP

#### 1. Онбординг

- 4 шага: тип питания → аллергии и ограничения → нелюбимые продукты → количество порций.
- На каждом шаге есть «Пропустить» и «Назад».
- Выбранное можно изменить позже в настройках.
- После завершения — автоподбор первой недели.
- Если все шаги пропущены, показываем нейтральный план и подсказку настроить предпочтения.

#### 2. План недели (главный экран)

- Неделя из 7 дней, начало — понедельник.
- Сегодняшний день выделен; при открытии план прокручивается к сегодня.
- В дне: блюда и заметка. Точное число приёмов пищи — открытый вопрос.
- У каждого дня есть видимая кнопка «+»: добавить рецепт или заметку.
- У блюда есть кнопка «⋯» с действиями: «Переместить», «Заменить», «Убрать». Без долгого нажатия.
- Повтор одного рецепта в неделе разрешён.
- Заметка заменяет блюдо: «остатки», «ужин в гостях», «готовлю из того, что есть».
- Меню недели: «Собрать заново», «Сохранить как шаблон», «Повторить сохранённую неделю».
- Пустое состояние: «Соберите первую неделю» + кнопка автоподбора.

#### 3. Выбор рецепта

- Открывается по «+» из дня или по «Заменить» у блюда. Это не отдельная вкладка каталога.
- Поиск по названию и ингредиентам.
- Фильтры-чипы: время готовки, тип блюда. Аллергии и тип питания применяются всегда и не сбрасываются вручную.
- Карточки с иллюстрацией, названием, временем и тегами.
- Действие «Добавить в день» сразу, без обязательного открытия рецепта.
- Если ничего не найдено: объяснение, список активных фильтров и кнопка «Сбросить фильтры». Если причина в аллергиях — ссылка в настройки, а не снятие защиты.

#### 4. Карточка рецепта

- Крупная иллюстрация, название, короткое вступление в 1–2 предложения в тёплом тоне.
- Метаданные: время, базовые порции, теги.
- Выбор порций: 2 / 4 / 6. Ингредиенты пересчитываются.
- Ингредиенты с количествами и единицами.
- Пошаговые инструкции на одном экране. Без полноэкранного кулинарного режима.
- Действия: «Добавить в план», «Добавить ингредиенты в покупки».
- Напоминание: «Проверьте состав, если у вас аллергия».
- Если рецепт уже есть в плане, повтор разрешён.

#### 5. Список покупок

- Собирается автоматически из блюд плана.
- Группировка по отделам магазина.
- Отметка купленного одним тапом, зачёркивание и возможность вернуть.
- Прогресс: «5 из 12 куплено».
- Ручное добавление позиции: поле сверху + автодополнение по каталогу ингредиентов.
- Ручные позиции не исчезают при изменении плана.
- При изменении плана автопозиции пересчитываются; отметки сохраняются для позиций, которые остались.
- Если блюдо удалено из плана, его автопозиции исчезают. Если ингредиент был добавлен вручную — остаётся.
- Одинаковые ингредиенты в одинаковых единицах суммируются. Разные единицы показываются отдельными строками с подсказкой «проверьте количество».
- Пустое состояние: «Список появится, когда в плане будут блюда. Можно добавить покупку вручную».

#### 6. Настройки (минимальные)

- Изменение предпочтений: тип питания, аллергии, нелюбимые продукты, порции.
- Повторный запуск онбординга.
- Работа с шаблоном: сохранить текущую неделю, применить сохранённую.
- Сброс всех данных с подтверждением.
- Короткий блок «О продукте» и дисклеймер про аллергены.
- Ничего лишнего: без профиля, аватара, тем и подписок.

### Навигация

- Нижняя навигация из 3 вкладок: «План», «Покупки», «Ещё».
- «Рецепты» не отдельная вкладка: подборка открывается из плана.
- Все действия — через видимые кнопки и тапы. Свайпы, долгие нажатия и перетаскивание не используем.
- Модальные экраны и панели открываются тапом; у каждого есть заметная кнопка закрытия.

### Правила подбора и ограничений

- Тип питания — жёсткий фильтр.
- Аллергены — жёсткий фильтр и в автоподборе, и в ручном выборе.
- Нелюбимые продукты — исключаются из автоподбора; в ручном выборе показываются с пометкой.
- Автоподбор распределяет блюда по дням, стараясь не повторять рецепты, но ручные повторы разрешены.
- Порции: 2 / 4 / 6. Множитель применяется к ингредиентам; яйца и штучные продукты округляются вверх. Перевод граммов в миллилитры и обратно не делаем.
- Повтор рецепта: порции складываются, одинаковые ингредиенты суммируются.
- Шаблон: одна сохранённая неделя. Применение заменяет текущую неделю после подтверждения.

### Данные и состояние

- Один ключ localStorage, например `tarelka:state`.
- В состоянии: версия схемы, профиль, активная неделя, шаблон, ручные позиции списка, отметки, флаг завершённого онбординга.
- При старте: чтение через `try/catch`, проверка версии, мягкая миграция известных полей.
- Повреждённые данные не перезаписываются молча: показываем понятное сообщение, сохраняем копию в отдельный ключ и предлагаем сброс.
- Сброс — только по явному подтверждению.
- Неделя хранится в виде локальных дат `YYYY-MM-DD`, без расчётов в UTC.
- Одна активная неделя и один шаблон. Истории недель и нескольких планов нет.

### Контент

- 18 рецептов в локальном JSON.
- Поля рецепта: `id`, название, описание, иллюстрация, время, базовые порции, теги, ингредиенты (название, количество, единица, отдел), шаги.
- Ингредиенты нормализованы: одинаковые названия и единицы должны совпадать, чтобы список суммировался.
- Иллюстрации: локальные SVG в `assets/recipes/`, по одному на блюдо.
- Категории списка: овощи и фрукты, мясо и рыба, молочное и яйца, бакалея, специи и соусы, заморозка, прочее.
- Тон текстов: тёплый, дружелюбный, без снобизма и канцелярита.

### Технические рамки

- Только HTML, CSS и JavaScript. Без фреймворков, библиотек и сборщиков.
- Mobile-first, responsive, PWA: manifest, иконки, service worker, офлайн-кеш оболочки, JSON и изображений.
- Все цвета — через токены в `styles/tokens.css`. В `main.css` и остальных стилях только `var(--...)`.
- Семантический HTML, aria-атрибуты, управление с клавиатуры, видимый фокус, зоны нажатия не меньше 44×44 px.
- Комментарии в коде — на русском.
- Данные не покидают устройство. Аналитики и трекинга нет.

### Критерии готовности MVP

- Новый пользователь проходит онбординг и получает план на неделю менее чем за 3 минуты.
- Можно добавить, заменить, переместить и убрать блюдо, добавить заметку.
- Повтор рецепта работает: порции и ингредиенты суммируются.
- Пересчёт порций 2/4/6 корректен для всех рецептов.
- Список собирается из плана, группируется, отмечается и сохраняет ручные позиции.
- После перезагрузки страницы состояние сохраняется.
- Приложение работает офлайн после первого открытия.
- Интерфейс проверен на ширине от 360 px, с клавиатуры и с включённым экранным диктором.

## Что НЕ делаем

Это явный out-of-scope MVP. Любой пункт можно вернуть только через отдельное обсуждение и обновление документа.

### Продукт и контент

- **Отдельная вкладка каталога рецептов.** В MVP рецепты выбираются из плана; полноценный каталог — после проверки сценария.
- **Избранное.** Повторное использование идёт через план и шаблон.
- **Кулинарный режим.** Пошаговые инструкции есть на карточке рецепта, но без полноэкранного режима, таймеров и Wake Lock.
- **«Рецепт дня» и лента вдохновения.** Главный экран — план, а не контентная лента.
- **Импорт рецептов по ссылке и свои рецепты.** Нужны парсинг, обход CORS и модерация.
- **Сообщество, рейтинги, отзывы, комментарии.** Отдельный продукт с модерацией.
- **Видеорецепты.** Дорого и не нужно для проверки гипотезы.
- **Нутрициология, дневник калорий, БЖУ, health score.** Медицинские риски и лишняя сложность.
- **AI-подбор и генерация.** В MVP работают правила и теги.
- **Калории как фильтр.** В MVP фильтруем по времени и типу блюда.

### Техника и данные

- **Аккаунты, авторизация, облачная синхронизация.** Противоречит модели «всё в localStorage».
- **Шаринг планов, списков и рецептов.** Нет бэкенда и аккаунтов.
- **Бэкенд, API, база данных.** Вне технических ограничений.
- **Несколько недель и история.** Только одна активная неделя и один шаблон.
- **Свайпы, долгие нажатия, drag-and-drop.** Выбран режим «только тапы».
- **Тёмная тема и кастомизация.** После MVP.
- **Мультиязычность и имперские единицы.** Русский язык и метрическая система.
- **Push-уведомления, аналитика, трекинг.** Нет бэкенда; приватность важнее.
- **Экспорт и импорт JSON.** В MVP не входит; кандидат на следующий этап.
- **Печать списка.** В MVP не входит; кандидат на следующий этап.
- **Доставка, магазины, цены, штрихкоды.** Нужны партнёрства и бэкенд.
- **Интеграции с календарём, Samsung Health и техникой.** Вне продукта.
- **Подписки, реклама, партнёрские ссылки.** На старте не монетизируем.
- **Настройки сверх минимальных.** Никаких профилей, аватаров и тем.

## Открытые вопросы

Эти решения нужны до SPEC или до начала соответствующей фичи.

1. **Приёмы пищи.** В дне только ужин или завтрак, обед и ужин? От этого зависит модель данных, автоподбор и высота экрана плана.
2. **Модель недели.** Неделя привязана к календарной (пн–вс) или это скользящие 7 дней? Что происходит в понедельник: план очищается, уходит в шаблон или ждёт ручного действия?
3. **Bottom sheet или полный экран.** Закрыт 5 ноября 2026: только полноэкранные диалоги (PRD A5), bottom sheet не используется.
4. **Печать и копирование списка.** Нужно ли в MVP копирование в буфер и печать, или откладываем?
5. **Контент.** Кто пишет 18 рецептов и рисует 18 SVG-иллюстраций? Нужен план по контенту до начала вёрстки.
6. **«Повторить сохранённую неделю».** Копируются ли заметки и порции? Заменяет ли шаблон текущую неделю сразу или после подтверждения?
7. **Новая неделя.** Что происходит с отметками и ручными позициями списка при переходе на новую неделю?
8. **Калории на карточке.** Показываем ли калории и БЖУ как справочную информацию, если они есть в данных, без дневника и расчётов?
9. **Имя шаблона.** Один безымянный шаблон или пользователь может назвать сохранённую неделю?
10. **Отделы магазина.** Утвердить финальный список категорий и порядок сортировки.
11. **Экспорт JSON.** Нужен ли как страховка от потери localStorage уже в MVP?
12. **Дисклеймер по аллергенам.** Утвердить формулировку и место: онбординг, карточка рецепта, настройки.
13. **Сброс отметок.** Нужна ли отдельная кнопка «Снять все отметки» или достаточно отмечать обратно вручную?

## Риски

| Риск | Вероятность | Влияние | Меры |
|---|---|---|---|
| Неполные данные об аллергенах | Средняя | Высокое | Консервативная разметка, жёсткий фильтр, заметный дисклеймер, ручная проверка контента |
| Ингредиенты не суммируются из-за разных единиц | Высокая | Среднее | Нормализация JSON, одинаковые названия и единицы, разные единицы — отдельными строками |
| Потеря данных в localStorage | Средняя | Высокое | Версия схемы, `try/catch`, копия повреждённых данных, подтверждение сброса, предупреждение о приватном режиме |
| Не успеваем с 18 рецептами и иллюстрациями | Высокая | Высокое | 18 рецептов, шаблон карточки, параллельная работа над контентом и кодом |
| Тяжёлые изображения и медленная загрузка | Средняя | Среднее | Локальные SVG, `loading="lazy"`, фиксированные размеры, бюджет веса на изображение |
| Разнобой в стиле иллюстраций | Средняя | Среднее | Единый шаблон SVG, ревью перед добавлением в каталог |
| «Только тапы» делает действия незаметными | Средняя | Среднее | Видимые кнопки «+» и «⋯», подписи, никаких скрытых жестов |
| Расползание объёма MVP | Высокая | Высокое | Этот документ — контракт; новые фичи только через обсуждение и обновление границ |
| Устаревший офлайн-кеш PWA | Средняя | Среднее | Версионирование кеша, обновление service worker, проверка после релиза |
| Ошибки дат и переходов через полночь | Низкая | Среднее | Локальные даты `YYYY-MM-DD`, без UTC-арифметики, тесты на границе недели |
| Недоступный интерфейс | Средняя | Среднее | Семантика, aria, фокус, клавиатура, контраст, зоны 44×44 px |
| Медицинские обещания в текстах | Средняя | Среднее | Дисклеймер, редактура, формулировки «подходит по тегам», а не «безопасно для аллергиков» |
| Случайный сброс данных | Низкая | Высокое | Подтверждение, копия состояния, понятное предупреждение |

## Следующий шаг

1. Закрыть открытые вопросы, которые влияют на модель данных: приёмы пищи, модель недели, новая неделя, шаблон.
2. Написать `docs/spec.md` с пользовательскими сценариями и состояниями экранов.
3. Согласовать план реализации.
4. Только после этого писать код: HTML → CSS через токены → JS.
