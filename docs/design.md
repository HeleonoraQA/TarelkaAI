**Версия:** 1.0  
**Дата:** 2 ноября 2026  
**Обновлено:** 5 ноября 2026  
**Статус:** на согласование  
**Связанные документы:** `docs/prd.md`, `docs/research.md`, `docs/discussion.md`, `AGENTS.md`

> Этот документ описывает визуальную концепцию MVP. Все цвета, отступы, радиусы и тени в реализации должны быть вынесены в CSS-переменные в `styles/tokens.css`. В `main.css` запрещены хардкод-цвета.

## 1. Мудборд

Tarelka не копирует конкурентов, а берёт из них только то, что помогает решить задачу «что готовить на неделю и что купить». Визуально продукт должен быть тёплым, спокойным и утилитарным одновременно.

### 1.1. Референсы из исследования

| Продукт | Ссылка | Что берём | Почему |
| :-- | :-- | :-- | :-- |
| **Mealime** | [mealime.com](https://www.mealime.com/) | Онбординг-квиз, готовый план с первого запуска, связка «план → список покупок», счётчик позиций. | Лучший пример того, как за 2–3 минуты довести пользователя до первого результата. Именно это и нужно Tarelka. |
| **Kitchen Stories** | [kitchenstories.com](https://www.kitchenstories.com/) | Тёплая редакционная подача рецепта, крупное фото, фокус на готовке. | Помогает сделать рецепт не сухим списком, а тёплым и понятным. Берём только подачу, без видео и медиаплатформы. |
| **AnyList** | [anylist.com](https://www.anylist.com/) | Удобство списка покупок, группировка по отделам, отметка одним тапом, скорость действий. | Эталон утилитарного UX. Берём удобство и предсказуемость, не копируя холодную эстетику. |
| **Whisk / Samsung Food** | [samsungfood.com](https://samsungfood.com/) | Структура недели, заметки к дню, сохранение недели как шаблона, понятные действия над блюдом. | Хорошие паттерны планирования, упрощённые под локальный MVP без аккаунтов и интеграций. |
| **Yummly** (исторический) | [Wikipedia: Yummly](https://en.wikipedia.org/wiki/Yummly) | Понятные фильтры-чипы и акцент на ограничениях. | Берём только фильтры. Не берём перегруженную сетку, агрегацию чужого контента и сложную персонализацию. |

### 1.2. Визуальная атмосфера

- **Тёплая домашняя.** Ассоциация с уютной кухней днём, естественным светом и домашней едой. Без стерильного «диетического» минимализма.
- **Спокойная.** Меньше визуального шума, больше воздуха. Фокус на плане и списке, а не на бесконечной ленте.
- **Дружелюбная.** Интерфейс должен ощущаться как заботливый, а не инструктивный. Тон — «как подруга на кухне».
- **Практичная.** Красота подчиняется скорости. Любое действие должно быть очевидным и доступным одной рукой.

## 2. Tone of Voice

Тон должен быть последовательным во всём микрокопирайте: кнопки, пустые состояния, ошибки, тосты.

### 2.1. Пять ключевых прилагательных

| Прилагательное | Пояснение |
| :-- | :-- |
| **Тёплый** | Без канцелярщины. Говорим по-человечески, с заботой. |
| **Спокойный** | Не давим, не торопим. Предлагаем, а не приказываем. |
| **Практичный** | Фокус на действии. Короткие фразы, максимум смысла. |
| **Дружелюбный** | Без снисходительности и без «улыбающегося робота». Естественный диалог. |
| **Честный** | Прямо говорим про ограничения (аллергии, фильтры). Никаких «100% безопасно», только понятные формулировки. |

### 2.2. Примеры микрокопира

| Контекст | Пример | Пояснение |
| :-- | :-- | :-- |
| **Кнопки (основные)** | `Собрать план`, `Добавить в план`, `Добавить ингредиенты в покупки`, `Сохранить`, `Готово` | Краткие глаголы в повелительном/деятельном виде. Без «Нажмите…». |
| **Кнопки (вторичные)** | `Изменить`, `Переместить`, `Заменить`, `Убрать`, `Закрыть`, `Отмена` | Понятные и однозначные. |
| **Пустое состояние (план)** | `Давайте соберём первую неделю` + кнопки `Собрать автоматически` / `Добавить вручную` | Приглашает к действию, не осуждает. |
| **Пустое состояние (покупки)** | `Пока тут пусто. Добавьте блюда в план — список соберётся сам.` | Объясняет причину и следующий шаг. |
| **Пустое состояние (поиск)** | `Ничего не нашли по запросу «кур».` + `Очистить поиск` / `Сбросить фильтры` | Честно говорит о результате, сразу предлагает решение. |
| **Фильтры (ограничения)** | `Учитываем: без глютена, без орехов` + `Изменить` | Подчёркивает, что ограничения жёсткие и остаются включёнными. |
| **Ошибки/предупреждения** | `Под эти условия пока нет рецептов` + `Изменить предпочтения` | Спокойное объяснение без «Ошибка!». |
| **Восстановление данных** | `Не удалось прочитать данные` + `Начать заново` / `Попробовать снова` | Честно, без паники. Акцент на безопасное действие. |
| **Аллергический дисклеймер** | `Мы исключаем рецепты с выбранными аллергенами, но состав продуктов может меняться. Проверяйте упаковку и состав.` | Короткий, предупредительный, без медицинских гарантий. |
| **Офлайн (предупреждение)** | `Данные не сохранятся` | Короткое предупреждение только при недоступности `localStorage`. |
| **Тосты** | `План готов. Можно менять.`, `Добавлено в Пн`, `Ингредиенты в покупках`, `Убрано` | Мягкие, без восклицательных знаков в большинстве случаев. |

## 3. Палитра

Палитра строится вокруг тёплых кремовых тонов с томатно-паприковым акцентом и приглушённым шалфеем для вторичных состояний. **Все значения только через CSS-переменные** в `styles/tokens.css`. Чистый белый `#FFFFFF` как основной фон **не используется**.

### 3.1. Основные токены

| Токен | HEX | Назначение | Психология цвета |
| :-- | :-- | :-- | :-- |
| `--color-bg` | `#FBF6EE` | Основной фон приложения | Тёплый крем. Мягче белого, меньше усталости глаз, создаёт домашнее ощущение. |
| `--color-surface` | `#FFFDF9` | Карточки, поля ввода, диалоги | Немного светлее фона, создаёт лёгкое разделение без резкого контраста. |
| `--color-surface-alt` | `#F4EBE0` | Чипы, вторичные блоки, пустые состояния | Приглушённый песочно-кремовый. Мягко выделяет без акцента. |
| `--color-text` | `#2E2622` | Основной текст | Тёплый тёмно-коричневый. Мягче чёрного, отлично читабелен. |
| `--color-text-muted` | `#6E625B` | Вторичный текст, подписи, метаданные | Приглушённый коричнево-серый. Снижает визуальную иерархию без потери читаемости. |

- Нажатая акцентная кнопка: `#FFF9F1` на `#8F2F20` — **7.73:1**.

## 4. Типографика

Типографика должна быть максимально читабельной на маленьком экране, хорошо работать с кириллицей и не требовать загрузки внешних шрифтов (соответствует NFR-D2, NFR-W5).

### 4.1. Шрифтовые семейства

| Назначение | Шрифтовая семья | Пояснение |
| :-- | :-- | :-- |
| **Заголовки (H1–H3)** | `"Inter", -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif` | Гуманистический гротеск. Крупные заголовки смотрятся чётко, отлично держат кириллицу. |
| **Текст, UI, кнопки (body, labels)** | `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif, "Apple Color Emoji", "Segoe UI Emoji"` | Системный стек. Мгновенная загрузка, нативное ощущение, максимальная совместимость. |

> Внешние шрифты не подключаются. `Inter` используется, только если он уже установлен в системе; иначе срабатывает системный стек. Это соответствует NFR-W5 и ограничению «никаких внешних запросов».

## 5. Spacing-шкала

Единая система отступов на базе 4 px. Упрощает вертикальные ритмы и выравнивание.

| Токен | Значение (px/rem) | Применение |
| :-- | :-- | :-- |
| `--space-1` | `4px / 0.25rem` | Очень мелкие зазоры: между иконкой и текстом в компактных элементах |
| `--space-2` | `8px / 0.5rem` | Минимальный отступ, выравнивание внутри чипа |
| `--space-3` | `12px / 0.75rem` | Отступы между связанными элементами, паддинги в мелких кнопках |
| `--space-4` | `16px / 1rem` | Базовый горизонтальный отступ экрана, стандартный паддинг карточки |
| `--space-5` | `24px / 1.5rem` | Отступ между секциями, вертикальный ритм карточек |
| `--space-6` | `32px / 2rem` | Крупные отступы между блоками |
| `--space-7` | `48px / 3rem` | Максимальные отступы (пустые состояния, разделы онбординга) |

## 6. Радиусы и тени

Мягкие, тёплые формы. Никаких острых углов, излишне «пузырчатых» скруглений и тяжёлых теней.

### 6.1. Радиусы

| Токен | Значение | Применение |
| :-- | :-- | :-- |
| `--radius-sm` | `8px` | Чипы, бейджи, маленькие элементы |
| `--radius-md` | `12px` | Поля ввода, мелкие карточки, меню-элементы |
| `--radius-lg` | `16px` | Основные карточки рецептов, полноэкранные диалоги |
| `--radius-xl` | `24px` | Крупные кнопки, модалки с сильным акцентом |
| `--radius-pill` | `999px` | Пилюли-фильтры, счётчики, полностью округлые кнопки |

### 6.2. Тени

Тени очень мягкие, тёплые по тону. Создают ощущение приподнятости, не «висящей» пластины.

| Токен | Значение | Применение |
| :-- | :-- | :-- |
| `--shadow-xs` | `0 1px 1px rgba(46, 38, 34, 0.02)` | Лёгкое разделение, минимальная глубина |
| `--shadow-sm` | `0 1px 2px rgba(46, 38, 34, 0.04), 0 1px 1px rgba(46, 38, 34, 0.02)` | Карточки в списке, элементы на фоне |
| `--shadow-md` | `0 4px 10px rgba(46, 38, 34, 0.06), 0 2px 4px rgba(46, 38, 34, 0.04)` | Карточка рецепта, активные элементы |
| `--shadow-lg` | `0 10px 30px rgba(46, 38, 34, 0.08), 0 4px 10px rgba(46, 38, 34, 0.05)` | Полноэкранные диалоги, выпадающие меню |

### 6.3. Переходы

| Токен | Значение | Применение |
| :-- | :-- | :-- |
| `--transition-fast` | `150ms ease-out` | Ховеры/фокусы, переключение состояний чипов/кнопок |
| `--transition-base` | `200ms ease-out` | Появление тостов, переключение вкладок |
| `--transition-slow` | `250ms ease-out` | Открытие полноэкранного диалога |

Учитывать `prefers-reduced-motion`: при включённой настройке переходы сводятся к `none`.

## 7. Иконография

### 7.1. Набор

Использовать **[Lucide Icons](https://lucide.dev/)**. Альтернатива — **Feather Icons**, при условии единообразия.

### 7.2. Правила

| Параметр | Значение | Пояснение |
| :-- | :-- | :-- |
| **Стиль** | Линейный (outline) | Минимум, утилитарный, вписывается в тёплый минимализм. |
| **Толщина обводки** | `stroke-width: 2px` | Чёткий, но не грубый. Хорошо читается на мобильном. |
| **Размер базовый** | `20px` | Для большинства UI-иконок (кнопки, навигация). |
| **Размер крупный** | `24px` | Для действий в карточке, важные кнопки. |
| **Размер мелкий** | `16px` | Для бейджей, inline-элементов. |
| **Цвет** | Наследует текстовый цвет (`currentColor`) | Упрощает состояния (focus/hover/disabled). |
| **Доступность** | `aria-hidden="true"`, если есть текстовая подпись, иначе `aria-label` | Исключает дублирование для скринридеров. |
| **Зоны нажатия** | Минимум `44×44px` | Оборачивать иконку в кликабельную зону при необходимости. |

## 8. Компоненты с ASCII-схемами

Все компоненты должны использовать токены из разделов 3–6. Интерактивные зоны — не менее 44×44 px. Для полноэкранных диалогов обязателен видимый элемент закрытия (`X` или «Назад»).

### 8.1. Карточка рецепта

Используется в выборе рецепта, в поиске и в превью. Иллюстрация — главный герой.

```text
┌─────────────────────────────────────────┐
│                [SVG 16:9]               │  (object-fit: cover, alt обязателен)
├─────────────────────────────────────────┤
│ Название рецепта                        │  (H3, color: --color-text)
│ Короткое вступление 1–2 предложения     │  (Body, color: --color-text)
├─────────────────────────────────────────┤
│  [clock 25 мин]  [users 2 порц.] [тег]  │  (Caption, color: --color-text-muted)
├─────────────────────────────────────────┤
│                [ + Добавить ]           │  (Кнопка, radius-pill, accent)
└─────────────────────────────────────────┘
```

**Спецификация:**

- Контейнер: `background: var(--color-surface)`, `border-radius: var(--radius-lg)`, `box-shadow: var(--shadow-md)`, `overflow: hidden`.
- Иллюстрация: локальный SVG, соотношение 16:9, `loading="lazy"` для карточек ниже первого экрана, заданы `width`/`height`.
- Метаданные: горизонтальный флекс с `gap: var(--space-3)`.
- Кнопка: полноширинная или с отступами, зона клика ≥ 44×44 px.
- При наличии нелюбимого ингредиента в ручном выборе — бейдж `Содержит …` (`--color-warning-soft`, `--color-warning-soft-text`).
- При несоответствии новым ограничениям — предупреждающий бейдж с текстом, не только цветом.

### 8.2. Chip-фильтр

Горизонтальные пилюли для фильтров времени/типа блюда. Активное состояние явно отличимо.

```text
[  До 20 мин  ]   [  Основное  ]   [  Закуска  ]   ...
   (неактивный)     (активный)      (неактивный)
```

**Спецификация:**

- Базовый: `background: var(--color-surface-alt)`, `color: var(--color-text)`, `border: 1px solid var(--color-border)`, `border-radius: var(--radius-pill)`, `padding: 6px 12px`, `min-height: 36px`.
- Активный: `background: var(--color-accent-soft)`, `color: var(--color-accent-soft-text)`, `border-color: transparent`, `aria-pressed="true"`.
- Фокус: `outline: 3px solid var(--color-focus)`, `outline-offset: 2px`.
- Горизонтальный скролл без обрезки фокуса, с `gap: var(--space-2)`.
- «Сбросить фильтры» — текстовая кнопка с `color: var(--color-accent)`.

### 8.3. Диалог вместо bottom sheet

Согласно PRD (A5) в MVP используются **полноэкранные диалоги/экраны**, а не bottom sheet. Это следствие режима «только тапы» и требований доступности. Реализовано 5 ноября 2026: полноэкранный диалог на всех ширинах, контент колонкой до 760 px. Ниже — основной вариант и справочная схема bottom sheet на случай будущего пересмотра.

#### Полноэкранный диалог (приоритет MVP)

```text
┌─────────────────────────────────────────┐
│  [← Назад / X]   Заголовок диалога      │  (Header, фиксированный)
├─────────────────────────────────────────┤
│                                         │
│           Контент диалога               │  (Скроллируемый)
│                                         │
├─────────────────────────────────────────┤
│              [ Основное действие ]      │  (Футер с кнопкой, при необходимости)
└─────────────────────────────────────────┘
```

**Спецификация:**

- Контейнер: `background: var(--color-bg)`, `inset: 0`, `z-index: 1000`.
- Header: `padding: var(--space-4)`, с видимой кнопкой закрытия, `aria-label` при иконке.
- Фокус-трап: при открытии фокус на первом интерактивном элементе или кнопке закрытия; `Esc` закрывает; фокус возвращается на инициатор.
- Скролл: только контентная область.
- Анимация: `--transition-slow`.

#### Bottom sheet (справочно, не для MVP)

```text
┌─────────────────────────────────────────┐
│                [——— ручка ———]          │  (grab-handle, визуальный индикатор)
├─────────────────────────────────────────┤
│ Заголовок                               │
│ ...                                     │
│ [ Действие 1 ]                          │
│ [ Действие 2 ]                          │
│ [ Отмена ]                              │
└─────────────────────────────────────────┘
```

**Спецификация (если вернутся):** `border-radius: var(--radius-lg) var(--radius-lg) 0 0`, `box-shadow: var(--shadow-lg)`, ручка `width: 40px; height: 4px; border-radius: 2px; background: var(--color-border-strong)`, затемнение фона. Жест закрытия свайпом не используется — только видимая кнопка.

### 8.4. Чекбокс списка покупок

Чекбокс должен быть крупным, с явным зачёркиванием и сохранением позиции строки.

```text
┌─────────────────────────────────────────────────────────┐
│  [✓]  Молоко, 1 л                        |  молочное     │
│       (зачёркнуто, цвет --color-text-muted)              │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│  [ ]  Лук репчатый, 500 г                |  овощи        │
│       (обычное состояние)                                │
└─────────────────────────────────────────────────────────┘
```

**Спецификация:**

- Контейнер строки: `min-height: 56px`, `padding: var(--space-3) var(--space-4)`, `display: flex`, `align-items: center`, `gap: var(--space-3)`.
- Чекбокс: `width: 24px; height: 24px`, `border-radius: 6px` (единообразно), `border: 1.5px solid var(--color-border-strong)`, зона клика ≥ 44×44 px.
- Отмеченное: `background: var(--color-sage)`, `border-color: var(--color-sage)`, иконка `check` цветом `--color-inverse`.
- Текст: `color: var(--color-text)`; при отмеченном — `text-decoration: line-through`, `color: var(--color-text-muted)`.
- Группировка по отделу: заголовок отдела с цветом текста `--color-dept-*-text` и мягким фоном `--color-dept-*-bg`.
- Бейджи: «вручную», «из рецепта», «по вкусу» — `--color-surface-alt`, мелкий текст `Caption`.
- Прогресс: «X из Y куплено» в `Caption`, цвет `--color-text-muted`; при 100% — `--color-sage` и текст «Всё куплено».

**Доступность:**

- Использовать нативный `input[type=checkbox]` с кастомной стилизацией или `role="checkbox"` с `aria-checked`. Предпочтителен нативный элемент.
- Вся строка кликабельна, но фокус должен быть на чекбоксе/элементе управления.
- Обновление прогресса анонсировать через `aria-live="polite"`.

## 9. Что НЕ используем

Строгое «не использовать», чтобы сохранить заявленный тон и соответствовать ограничениям проекта.

| Категория | Что не используем | Почему |
| :-- | :-- | :-- |
| **Фон** | Чистый белый `#FFFFFF` как основной фон | Слишком стерильный. Используем тёплый крем `--color-bg`. |
| **Цвета** | Ярко-синий, неоновый, кислотный, холодный циановый | Не вписываются в тёплую домашнюю атмосферу. |
| **Акценты** | Тёмно-синий/фиолетовый как основной акцент | Холодные, контрастируют с желаемым «кухонным» тоном. |
| **Формы** | Острые углы `0–4px` для карточек/кнопок | Слишком жёсткие. Минимум `--radius-sm`. |
| **Формы** | Слишком большие скругления `32px+` везде | Могут выглядеть игрушечно. Используем `16–24px` точечно. |
| **Тени** | Жёсткие чёрные тени, резкие блёклые тени, градиентные тени | Создают грязный эффект. Только мягкие тёплые. |
| **Градиенты** | Фоновые градиенты, градиенты на кнопках | Излишние, ухудшают читаемость, не соответствуют спокойному стилю. |
| **Типографика** | Декоративные display-засечки, моноширинные для основного текста | Меньше читаемы на мобильном, избыточны для UI. |
| **Иконки** | Заполненные (filled) иконки везде, микс разных стилей/толщин | Нарушают единообразие. Только линейные, `stroke-width: 2px`. |
| **Изображения** | Перегруженные стоковые кадры в стерильной студии, излишне обработанные HDR | Хотим естественный свет, домашнюю еду, аппетитную, но не глянцевую подачу. |
| **Анимации** | Длинные (> 300 ms), параллакс, излишние трансформации | Могут мешать использованию. Максимум 250 ms, с учётом `prefers-reduced-motion`. |
| **UI-паттерны** | Свайпы, лонг-пресс, drag-and-drop, бесконечная лента | Противоречат требованию «только тапы» (PRD 1.2, 3.2). |
| **Контент** | Медицинские формулировки «безопасно», «подходит аллергикам» | Недопустимо для немедицинского продукта. Только «исключаем рецепты с выбранными аллергенами» + дисклеймер. |
| **Прочее** | Тёмная тема в MVP, кастомизация шрифтов, мультиязычность, эмодзи как единственный способ донести смысл | Вне границ MVP (PRD 3.2). |

**Главный принцип:** меньше декора — больше ясности. Если элемент можно убрать без потери понимания — убираем его.
